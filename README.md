# سامانه مدیریت بازدیدکنندگان نمایشگاه — امن‌آفرینان

سامانه‌ای سبک، فارسی و کاملاً راست‌به‌چپ برای ثبت سریع بازدیدکنندگان و مشتریان نمایشگاه‌های
**امن‌آفرینان** در غرفه‌های نمایشگاهی. کارمند غرفه در کمتر از ۶۰ ثانیه یک بازدیدکننده را ثبت
می‌کند و مدیر سیستم می‌تواند گزارش بگیرد، پیگیری مشتریان را مدیریت کند و خروجی اکسل بگیرد.

این سامانه یک CRM کامل نیست؛ عمداً سبک و سریع نگه داشته شده، اما اسکیمای پایگاه داده برای
یکپارچه‌سازی‌های آینده (وب‌سایت، فروشگاه اینترنتی، ماژول PrestaShop) توسعه‌پذیر طراحی شده است.

## ۱. قابلیت‌های پیاده‌سازی‌شده

### احراز هویت و دسترسی
- ورود با نام کاربری و رمز عبور؛ رمزها با bcrypt هش می‌شوند (plain text ذخیره نمی‌شود).
- نشست بر پایه **کوکی HttpOnly** + توکن JWT (بدون ذخیره توکن در localStorage).
- محافظت **CSRF** با الگوی double-submit برای همه درخواست‌های تغییردهنده وضعیت.
- دو نقش: **مدیر سیستم (ADMIN)** و **کارمند غرفه (EMPLOYEE)**.
- کنترل دسترسی **در سمت سرور** (نه فقط پنهان کردن دکمه‌ها): کارمند فقط رکوردهای خودش را می‌بیند.
- محدودیت نرخ درخواست روی ورود (express-rate-limit) و روی کل API.
- ثبت لاگ حسابرسی برای عملیات حساس (ورود، ساخت کاربر، تغییر نقش، خروجی اکسل، …).

### ثبت بازدیدکننده (سریع و موبایل‌محور)
- فرم تک‌صفحه‌ای با دکمه‌های انتخابی برای جنسیت، نوع درخواست و اولویت (تایپ حداقلی).
- کیبورم مناسب موبایل (tel/numeric)، پشتیبانی از ارقام فارسی/عربی و تبدیل خودکار به لاتین.
- اعتبارسنجی شماره موبایل ایرانی (پشتیبانی از ۰۹۱۲…، ‎+98912…‎، ‎0098912…‎ و …).
- جلوگیری از ارسال تکراری فرم و نمایش پیام موفقیت + دکمه «ثبت بازدیدکننده بعدی».
- **تشخیص بازدیدکننده تکراری** پیش از ثبت (هشدار + نمایش سابقه) بدون جلوگیری از ثبت و
  بدون حذف یا بازنویسی رکورد قبلی.

### نمایشگاه‌ها و کارمندان
- مدیریت کامل نمایشگاه‌ها (نام، مکان، تاریخ شروع/پایان، توضیح، وضعیت).
- هر بازدیدکننده به یک نمایشگاه متصل است؛ هیچ نام نمایشگاهی در کد hardcode نشده است.
- ساخت/ویرایش/فعال‌سازی/غیرفعال‌سازی/حذف کارمندان، بازنشانی رمز، تعیین نقش و نمایشگاه فعال.

### داشبورد و گزارش‌ها
- داشبورد مدیریتی: کل بازدیدکنندگان، ثبت امروز، سرنخ‌های داغ، در انتظار پیگیری، نرخ رضایت بازاریابی.
- نمودارها: روند روزانه، تفکیک نمایشگاه/کارمند/نوع درخواست/اولویت/وضعیت پیگیری/پلتفرم پیام.
- جدول بازدیدکنندگان با جست‌وجو (نام، موبایل، شرکت)، فیلترهای ترکیبی و **صفحه‌بندی و مرتب‌سازی در سمت سرور**.
- صفحه مدیریت پیگیری با وضعیت‌های جدید / تماس گرفته شد / در مذاکره / نهایی شده / رد شده.

### پیام‌رسانی
- قالب‌های پیام قابل ویرایش توسط مدیر (تشکر، معرفی شرکت، معرفی محصول، کاتالوگ، پیگیری).
- متغیرهای پویا: `{name}`، `{company}`، `{mobile}`، `{exhibition}`، `{employee}`، `{catalog_url}`.
- لینک بازکردن پیام‌رسان با متن آماده: WhatsApp، Telegram، بل، ایتا.
- **صفحه اتصال پیام‌رسان‌ها** (`/admin/connections`): مدیریت توکن و تنظیمات اتصال هر پلتفرم + آزمایش اتصال.
- تفکیک کامل وضعیت‌ها: درخواست نشده / آماده‌سازی شد / باز شد توسط کارمند / **ارسال تأییدشده توسط کارمند** /
  ارسال‌شده با API / ناموفق. سامانه هرگز بدون تأیید کارمند، پیام را «ارسال‌شده» ثبت نمی‌کند.
- ثبت تاریخچه پیام برای هر مراجعه.
- راهنمای گام‌به‌گام اتصال به هر پلتفرم در `docs/CONNECTIONS.md`.

### رضایت بازاریابی
- رضایت بازاریابی **جدا از** درخواست پیام تشکر ثبت می‌شود.
- ذخیره زمان رضایت، پلتفرم انتخابی و بافت رضایت (نام نمایشگاه).
- اعتبارسنجی: رضایت بازاریابی بدون انتخاب پلتفرم مجاز نیست.

### خروجی اکسل و PDF
- تولید واقعی فایل xlsx با ExcelJS و فایل PDF با PDFKit (بدون داده ساختگی).
- ستون‌های فارسی، عرض ستون مناسب، تاریخ شمسی + میلادی، شیت جداگانه آمار خلاصه.
- خروجی با فیلترهای فعال: همه، یک نمایشگاه، یک کارمند، بازه تاریخی، سرنخ‌های داغ، وضعیت پیگیری.
- فایل اکسل با کدگذاری UTF-8 و جهت راست‌به‌چپ (rightToLeft) ساخته می‌شود.
- فایل PDF با فونت وزیرمتن، جدول راست‌به‌چپ و صفحه‌بندی خودکار تولید می‌شود.

### رابط کاربری
- فارسی کامل، `dir="rtl"`، فونت Vazirmatn، طراحی mobile-first.
- تقویم شمسی (Jalali) با انتخاب سریع و تبدیل خودکار ارقام فارسی.
- شماره موبایل و ایمیل همیشه چپ‌به‌راست نمایش داده می‌شوند.
- تاریخچه پیگیری و پیام برای هر بازدیدکننده.

## ۵. نصب و راه‌اندازی توسعه

~~~bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) تنظیمات محیطی
cp .env.example server/.env
# سپس JWT_SECRET و ADMIN_PASSWORD را در server/.env تغییر دهید

# ۳) ساخت کلاینت Prisma و جدول‌ها
npm run db:generate
npm run db:push          # یا: npm run db:migrate

# ۴) ساخت حساب مدیر و قالب‌های پیام
npm run db:seed

# ۵) اجرای همزمان فرانت‌اند و بک‌اند
npm run dev
# فرانت‌اند: http://localhost:5173   |   API: http://localhost:4000
~~~

پروکسی توسعه به‌صورت خودکار در client/vite.config.ts تعریف شده است، بنابراین فرانت‌اند
درخواست‌های /api را به بک‌اند می‌فرستد.

### ساخت حساب مدیر

- با دستور db:seed یک حساب مدیر با نام کاربری و رمز ADMIN_USERNAME / ADMIN_PASSWORD ساخته می‌شود.
- برای ساخت حساب مدیر دیگر، همان دستور را با متغیرهای محیطی دلخواه اجرا کنید یا از پنل
  «مدیریت کارمندان» استفاده کنید.
- پس از اولین ورود، رمز عبور را تغییر دهید (حساب‌های ساخته‌شده با mustChangePassword مجبور به تغییر رمز هستند).

## ۶. متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| NODE_ENV | development | production در محیط عملیاتی |
| PORT | 4000 | پورت API |
| DATABASE_URL | file:./dev.db | مسیر SQLite (نسبت به پوشه prisma/) |
| JWT_SECRET | — | **در production الزامی**؛ حداقل ۳۲ کاراکتر تصادفی |
| JWT_EXPIRES_IN | 8h | عمر توکن |
| COOKIE_SECURE | false | در production روی HTTPS باید true باشد |
| COOKIE_SAME_SITE | lax | برای دامنه جداگانه: none به‌همراه HTTPS |
| TRUST_PROXY | false | پشت nginx معکوس روی true قرار دهید |
| CORS_ORIGIN | http://localhost:5173 | دامنه‌های مجاز، جداشده با کاما |
| LOGIN_MAX_ATTEMPTS | 10 | سقف تلاش ناموفق ورود |
| API_RATE_LIMIT | 600 | سقف درخواست در هر بازه |
| ADMIN_USERNAME / ADMIN_PASSWORD | admin / Admin@12345 | حساب مدیر اولیه |

نمونه کامل در فایل .env.example قرار دارد.

## ۱۱. قابلیت‌هایی که به کلید یا مجوز API خارجی نیاز دارند

هیچ‌کدام از این موارد در کد ادعای «ارسال خودکار» نمی‌کنند و تا زمانی که اطلاعات معتبر
در اختیار سامانه قرار نگیرد، غیرفعال هستند:

| قابلیت | وضعیت فعلی | پیش‌نیاز فعال‌سازی |
|---|---|---|
| ارسال پیام از طریق API (واتساپ بیزینس) | اتصال قابل تنظیم از صفحه «اتصال پیام‌رسان‌ها» | توکن WhatsApp Business Cloud API + شماره تأییدشده |
| ارسال پیام از طریق API (تلگرام) | اتصال قابل تنظیم از صفحه «اتصال پیام‌رسان‌ها» | توکن ربات تلگرام و مجوز ارسال به کاربر خاص (تلگرام به شماره دلخواه پیام نمی‌فرستد) |
| ارسال پیام از طریق API (بل / ایتا) | اتصال قابل تنظیم از صفحه «اتصال پیام‌رسان‌ها» | توکن API و تأیید رسمی پشتیبانی |
| ورود یکپارچه با سایت یا CRM | پیاده‌سازی نشده | مشخصات API مقصد |
| ارسال ایمیل کاتالوگ | پیاده‌سازی نشده | سرویس ایمیل (SMTP یا SendGrid) و دامنه ارسال‌کننده |
| فونت و آیکون محلی | فونت Vazirmatn به‌صورت محلی | — |

راهنمای گام‌به‌گام اتصال به هر پلتفرم در `docs/CONNECTIONS.md` موجود است.

ساختار کد برای افزودن این قابلیت‌ها آماده است: کافی است در
server/src/services/message.service.ts یک ارائه‌دهنده جدید اضافه و وضعیت API_SENT را
تنها پس از پاسخ موفق API ثبت کنید.

## ۱۲. نکات فنی و محدودیت‌ها

- SQLite با حالت WAL برای خواندن و نوشتن همزمان مناسب است؛ برای حجم بالای چند صد هزار
  مراجعه می‌توان بعداً به PostgreSQL مهاجرت داد (Prisma این مهاجرت را ساده می‌کند).
- لینک‌های بل و ایتا بر پایه الگوی عمومی share هستند و باید روی دستگاه واقعی آزمایش شوند؛
  در صورت نبود لینک، متن پیام آماده و قابل کپی است.
- گزارش «پیام ارسال‌شده» فقط با تأیید صریح کارمند ثبت می‌شود.
